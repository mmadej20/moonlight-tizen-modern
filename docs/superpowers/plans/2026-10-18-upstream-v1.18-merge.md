Master po 1.18.0 to osobny, opcjonalny etap B.

**Tech Stack:** git 2.51, Node (testy JS, `npm run test:js`), g++ 13 w WSL Ubuntu-24.04 (testy natywne z ASan/UBSan), Docker 28 (Tizen Studio 6.1, Samsung Emscripten 1.39.4.7), jQuery 2.2.0.

## Review Focus

Wejścia i awarie, które specyfikacja implikuje, a które samo `git merge` łatwo psuje (każde ma test w Zadaniu 2):

1. **Kolejność argumentów `startStream`** (JS → `messages.js` → embind → `StartStream`): ponad 25 argumentów pozycyjnych, przestawienie dwóch booleanów kompiluje się i cicho przesuwa ustawienia (`decryptHostAudio` wchodzi w środek listy, `speculativeRfi` zostaje na końcu).
2. **Backend audio „Disabled” przy lokalnym oczekiwaniu na tory EMSS**: start nie może czekać na tor audio, `AudDecCleanup` musi znosić `AudDecInit` zakończony wcześniej, a diagnostyka audio nie może raportować fałszywych stalli.
3. **Stare zapisane ustawienia po aktualizacji**: brak `decryptHostAudio`/`Disabled`/per-host Auto WoL → wartości domyślne; zapisane `false`/`0` zostają.
4. **Host sparowany vs niesparowany w `refreshServerInfoAtAddress`**: sparowany tylko HTTPS (także po niezgodności certyfikatu), niesparowany nadal HTTP; każde `openUrl` niesie lokalny argument timeoutu (5000), którego upstream nie przekazuje.
5. **Dane z hosta renderowane jako HTML** (upstream naprawił XSS w 1.17.2): lokalny dialog logów, nazwy hostów/aplikacji i okno aktualizacji nie mogą wstawiać niezaufanych napisów przez `.html()`/`innerHTML`.
